# Obsidian Patch Pack — правила обновления

## Статус
Рабочий метод обновления Obsidian-проекта «Альфа001».

## Суть метода
Больше не пересоздавать и не выдавать весь архив Obsidian целиком при каждом обновлении. Вместо этого выдавать пакет правок:
- новые markdown-файлы;
- обновлённые markdown-файлы только при необходимости;
- инструкции, какие разделы добавить в существующие заметки;
- changelog;
- краткий GitHub update.

## Главные правила
- Не пересобирать весь проект.
- Не удалять старые заметки.
- Не сокращать старый текст.
- Не заменять подробный лор кратким пересказом.
- Не создавать дубликаты папок и заметок.
- Не смешивать канон и черновики без пометки.

## Формат пакета
Каждый пакет должен содержать:
1. README или инструкцию.
2. Список новых файлов.
3. Список правок в существующие файлы.
4. Раздел “Что не трогать”.
5. Changelog.
6. GitHub update.

## Когда создавать новый файл
Новый файл создаётся только если:
- нет подходящей существующей заметки;
- тема стала достаточно крупной;
- файл нужен как банк идей;
- пользователь попросил отдельный файл;
- старая заметка станет перегруженной.

## Когда дописывать старую заметку
Если тема уже существует, добавлять новую информацию в конец как:
- `## Дополнение`
- `## Уточнение`
- `## Обновление концепции`
- `## Черновая идея`
- `## Закреплено в каноне`

## Проверка перед выдачей
- Новые файлы лежат в существующих папках.
- Старые файлы не удалены.
- Нет дублей.
- Идеи имеют статус.
- Канон, режим письма и редактура не смешаны.
- Удалённые исходные копии писательских инструкций не создаются заново; единственный полный корпус находится в строгом и редакторском master-файлах.
- При создании художественного текста выбран ровно один режим через [[00_ВЫБОР_РЕЖИМА_ПИСЬМА]].
- Changelog добавлен.
- GitHub update добавлен.
